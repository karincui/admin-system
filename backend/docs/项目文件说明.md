# backend-karin 项目文件说明

> 面向前端转后端同学。可对照理解：`pom.xml` ≈ `package.json`，`Controller` ≈ 路由处理，`Service` ≈ 业务逻辑，`Repository/Entity` ≈ 数据层。

---

## 0. 整体结构一览

```text
backend-karin/
├── pom.xml                          # 依赖与构建（≈ package.json）
├── mvnw / mvnw.cmd                  # Maven Wrapper（免装 Maven）
├── .mvn/wrapper/                    # Wrapper 配置
├── docker-compose.yml               # 本地 MySQL 容器
├── .gitignore
├── README.md
├── docs/
│   └── 项目文件说明.md              # 本文档
└── src/
    ├── main/
    │   ├── java/com/karin/backend/
    │   │   ├── BackendKarinApplication.java
    │   │   ├── common/              # 统一响应、异常
    │   │   ├── config/              # CORS、Swagger、初始管理员
    │   │   ├── module/
    │   │   │   ├── auth/            # 登录
    │   │   │   └── user/            # 用户
    │   │   └── security/            # JWT、权限过滤器
    │   └── resources/
    │       ├── application.yml
    │       ├── application-dev.yml
    │       ├── application-prod.yml
    │       └── db/migration/        # Flyway SQL
    └── test/                        # 测试
```

一次请求的大致链路：

```text
前端请求
  → Controller（接 HTTP）
  → Service（业务）
  → Repository + Entity（读写 MySQL）
  → Security / JWT（登录发牌、之后验牌）
  → ApiResponse（统一 JSON 返回）
```

## 1. 工程与运行相关

### `pom.xml`

Maven 项目描述文件。

- 声明 Java 版本、Spring Boot 版本
- 声明依赖：Web、JPA、MySQL、Security、Flyway、JWT、Swagger、Lombok 等
- 相当于前端的 `package.json` + 部分构建配置

### `mvnw` / `mvnw.cmd`

Maven Wrapper 脚本。

- 本机没全局安装 Maven 也能构建、启动
- Windows 用：`.\mvnw.cmd spring-boot:run`
- macOS / Linux 用：`./mvnw spring-boot:run`

### `.mvn/wrapper/maven-wrapper.properties`

Wrapper 配置：指定下载哪一版 Maven、从哪个地址下载。

### `.mvn/wrapper/maven-wrapper.jar`

Wrapper 实际执行用的小工具（一般不用手改）。

### `docker-compose.yml`

用 Docker 一键启动本地 MySQL。

- 库名：`karin`
- 账号：`karin` / `karin123`
- 宿主机端口：**3307**（避免和本机已安装的 MySQL 3306 冲突）
- 容器内仍是 3306

常用命令：

```bash
docker compose up -d      # 启动
docker compose ps         # 看状态
docker compose down       # 停止（默认保留数据卷）
docker compose down -v    # 停止并删除数据（慎用）
```

### `.gitignore`

告诉 Git 忽略哪些文件，例如：

- `target/`（编译产物）
- `.idea/`（IDE 配置）
- `.env`（密钥）

避免把构建结果和敏感信息提交进仓库。

### `README.md`

项目使用说明：如何启动、默认账号、主要接口。

## 2. 配置文件（`src/main/resources`）

### `application.yml`

公共配置（所有环境都会加载）。

主要包含：

- 应用名
- 服务端口（默认 8080）
- 激活哪个 profile（当前默认 `dev`）
- JWT 默认密钥与过期时间
- Swagger / Actuator 基础路径

### `application-dev.yml`

**开发环境**专用配置。

- 数据源指向 `localhost:3307`
- 打开 Hibernate SQL 日志，方便学习排查
- 开启 Flyway 自动迁移

本地开发主要改这个文件。

### `application-prod.yml`

**生产环境**专用配置。

- 数据库地址、账号、密码从环境变量读取（`DB_URL` / `DB_USER` / `DB_PASSWORD`）
- 日志更安静
- Actuator 只暴露 `health`

部署服务器时用：

```bash
java -jar app.jar --spring.profiles.active=prod
```

### `db/migration/V1__init.sql`

Flyway 第 1 版数据库迁移脚本。

- 创建 `sys_user` 表
- 应用启动时自动执行（若尚未执行过）
- 相当于「可版本管理的建表 SQL」，不要靠手改生产库结构

命名规则：`V版本号__描述.sql`，例如 `V2__add_user_email.sql`。

## 3. 启动入口

### `BackendKarinApplication.java`

Spring Boot 主类。

- 含 `main` 方法，整个后端从这里启动
- `@SpringBootApplication` 会自动扫描同包及子包中的组件（Controller、Service、Config 等）

可以把它理解成后端的「入口文件」。

## 4. 公共层 `common/`

放全项目共用的约定，不绑具体业务。

### `ApiResponse.java`

统一响应体：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

前端只需按同一结构解析。`code == 0` 表示成功。

### `BusinessException.java`

业务异常。

例如：用户名密码错误、账号禁用。  
可携带业务错误码，被全局异常处理器捕获后转成统一 JSON。

### `GlobalExceptionHandler.java`

全局异常处理（`@RestControllerAdvice`）。

负责把各类异常转成友好响应，例如：

- 参数校验失败 → 400
- 未登录 → 401
- 无权限 → 403
- 未知错误 → 500

类似前端 axios 的「响应拦截器」，但是在服务端统一处理。

## 5. 配置类 `config/`

### `CorsConfig.java`

跨域配置。

允许前端开发服务器（如 `http://localhost:5173`）访问本后端，避免浏览器 CORS 拦截。

### `OpenApiConfig.java`

Swagger / OpenAPI 配置。

- 文档标题、描述
- 配置 Bearer JWT，方便在 Swagger 页面里点「Authorize」后调试需登录接口

访问地址：http://localhost:8080/swagger-ui.html

### `AdminUserInitializer.java`

应用启动初始化逻辑。

- 若数据库还没有 `admin` 用户，则自动创建
- 默认账号：`admin` / `admin123`
- 密码使用 BCrypt 加密后再入库（不明文存）

## 6. 登录模块 `module/auth/`

职责：处理登录，签发 JWT。

调用链：

```text
AuthController → AuthService → SysUserRepository → JwtService
```

### `AuthController.java`

HTTP 接口层。

- `POST /api/auth/login`
- 接收 JSON 入参，调用 Service，返回统一响应
- **尽量不写复杂业务**，只做「接请求 / 调服务 / 回结果」

前端类比：路由处理函数 / API Route。

### `AuthService.java`

登录业务逻辑。

1. 按用户名查用户
2. 检查是否启用
3. 用 `PasswordEncoder` 比对密码
4. 调用 `JwtService` 生成 token
5. 组装 `LoginResponse` 返回

### `LoginRequest.java`

登录请求 DTO（Data Transfer Object）。

字段：

- `username`
- `password`

带 `@NotBlank` 等校验注解，请求体不合法时由全局异常处理返回 400。  
前端类比：登录表单的 TypeScript 类型 + 校验规则。

### `LoginResponse.java`

登录成功返回给前端的数据。

- `token`：后续请求放在 `Authorization: Bearer <token>`
- `user`：用户基本信息

---

## 7. 用户模块 `module/user/`

职责：用户数据模型、查询、对外暴露的用户信息接口。

### `SysUser.java`

JPA **实体（Entity）**，对应表 `sys_user`。

主要字段：

- `id`
- `username`
- `passwordHash`（密码哈希，不是明文）
- `nickname`
- `role`
- `enabled`
- `createdAt` / `updatedAt`

`@PrePersist` / `@PreUpdate` 用于自动填创建/更新时间。

注意：Entity 是数据库映射对象，**一般不要直接当作接口返回值**（容易泄露密码哈希、触发懒加载问题）。

### `SysUserRepository.java`

数据访问层（Repository / DAO）。

- 继承 `JpaRepository<SysUser, Long>`，自带 `save` / `findById` / `findAll` / `delete` 等
- 额外声明：`findByUsername`、`existsByUsername`

Spring Data 会按方法名自动生成查询实现。

### `UserRole.java`

用户角色枚举：

- `ADMIN`
- `USER`

后续做权限控制时会用到（如 `ROLE_ADMIN`）。

### `UserResponse.java`

返回给前端的用户信息 DTO。

- 从 `SysUser` 转换而来
- **不包含** `passwordHash`
- 保证对外数据结构稳定、安全

### `UserController.java`

用户相关接口。

- `GET /api/users/me`：获取当前登录用户信息
- 通过 `@AuthenticationPrincipal LoginUser` 拿到当前用户
- 需要请求头携带有效 JWT，否则 401

## 8. 安全层 `security/`

职责：认证（你是谁）与鉴权（你能做什么）的基础设施。

### `SecurityConfig.java`

Spring Security 总配置。

- 关闭 CSRF（前后端分离 + JWT 常见做法）
- 使用无状态 Session（不靠服务器 Session 记登录）
- 配置放行路径：登录、Swagger、健康检查
- 其他请求必须认证
- 注册 JWT 过滤器
- 提供 `PasswordEncoder`（BCrypt）Bean
- 未登录 / 无权限时返回统一 JSON，而不是默认 HTML 错误页

前端类比：全局路由守卫的配置中心。

### `JwtProperties.java`

读取配置项：

- `app.jwt.secret`
- `app.jwt.expire-hours`

把配置文件里的值映射成 Java 对象，供 `JwtService` 使用。

### `JwtService.java`

JWT 工具服务。

- `createToken`：登录成功后签发 token（含 userId、username、role、过期时间）
- `parse`：解析并校验 token 签名与过期

### `JwtAuthenticationFilter.java`

JWT 认证过滤器（每个请求都会经过）。

流程：

1. 读请求头 `Authorization`
2. 若是 `Bearer xxx`，则解析 token
3. 解析成功则把当前用户放进 `SecurityContext`
4. 放行到后续 Controller

前端类比：axios 请求拦截器的「反向」——服务端验票。

### `LoginUser.java`

Spring Security 中的「当前登录用户」对象（实现 `UserDetails`）。

- 保存 id、username、role、权限列表等
- Controller 里可通过 `@AuthenticationPrincipal LoginUser` 直接使用

## 11. 分层口诀（建议记住）

1. **Controller**：只接参数、调 Service、返回结果  
2. **Service**：写业务规则（校验、权限判断、事务边界）  
3. **Repository**：只负责数据存取  
4. **Entity**：对应数据库表，不直接当对外 API 模型  
5. **DTO（Request/Response）**：专门给接口用的进出数据结构  
6. **Security**：统一处理登录态与访问控制  
7. **Flyway**：表结构变更走版本化 SQL，不靠手改生产库

## 12. 建议阅读顺序（第一次看代码）

1. `BackendKarinApplication.java` — 入口  
2. `application.yml` + `application-dev.yml` — 配置从哪来  
3. `AuthController` → `AuthService` — 登录怎么走  
4. `SysUser` + `SysUserRepository` + `V1__init.sql` — 数据和表  
5. `SecurityConfig` → `JwtAuthenticationFilter` → `JwtService` — 鉴权怎么做  
6. `UserController` — 带 token 后如何拿当前用户  
7. `ApiResponse` + `GlobalExceptionHandler` — 为什么返回格式统一  

按这个顺序看一遍，再打开 Swagger 实际登录调用，会快很多。

---

## 13. 一句话总结

这个项目是一个最小可用的后台后端骨架：**MySQL 存用户 → 登录签发 JWT → 过滤器验票 → Controller/Service 分层处理业务 → 统一 JSON 返回**。  
后续加「用户管理、角色权限、菜单、上传」等，都是在这个骨架上往 `module/` 里加模块。
