# 实施步骤：新增用户接口（Add User）

目标接口：

```http
POST /api/users
Authorization: Bearer <token>
Content-Type: application/json

{
  "username": "zhangsan",
  "password": "123456",
  "nickname": "张三",
  "role": "USER"
}
```

成功返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 2,
    "username": "zhangsan",
    "nickname": "张三",
    "role": "USER",
    "enabled": true,
    "createdAt": "..."
  }
}
```

表 `sys_user` 已存在（`V1__init.sql`），**这一步不用新建 Flyway**。

---

## 总览（按这个顺序做）

1. 写入参 DTO：`UserCreateRequest`
2. 在 `SysUserRepository` 确认有 `existsByUsername`（已有可跳过）
3. 新建 `UserService`，写 `create` 方法
4. 在 `UserController` 增加 `POST /api/users`
5. （推荐）限制仅管理员可新增
6. 重启，用 Swagger / curl 验证

参考现有代码：

- 入参校验：`module/auth/LoginRequest.java`
- 密码加密：`AuthService` 里的 `passwordEncoder.encode(...)`
- 返回体：`UserResponse.from(user)`
- 统一响应：`ApiResponse.ok(...)`
- 业务错误：`BusinessException`

## 第 1 步：创建 `UserCreateRequest.java`

路径：

```text
backend/src/main/java/com/karin/backend/module/user/UserCreateRequest.java
```

建议内容：

```java
package com.karin.backend.module.user;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import lombok.Data;

@Data
public class UserCreateRequest {

    @NotBlank(message = "用户名不能为空")
    @Size(min = 3, max = 64, message = "用户名长度 3~64")
    private String username;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 64, message = "密码长度 6~64")
    private String password;

    @Size(max = 64, message = "昵称最多 64 字")
    private String nickname;

    // 可选；不传则默认 USER
    private UserRole role;
}
```

你要自己确认：

- 字段是否够用（先这 4 个就行）
- `role` 要不要必填（建议可选，默认 `USER`）

## 第 3 步：新建 `UserService.java`

路径：

```text
backend/src/main/java/com/karin/backend/module/user/UserService.java
```

核心逻辑（自己敲，别整段盲贴也行）：

```java
package com.karin.backend.module.user;

import com.karin.backend.common.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@RequiredArgsConstructor
public class UserService {

    private final SysUserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    @Transactional
    public UserResponse create(UserCreateRequest request) {
        // 1) 用户名唯一
        if (userRepository.existsByUsername(request.getUsername())) {
            throw new BusinessException(409, "用户名已存在");
        }

        // 2) 组装实体
        SysUser user = new SysUser();
        user.setUsername(request.getUsername());
        user.setPasswordHash(passwordEncoder.encode(request.getPassword())); // 绝不明文
        user.setNickname(request.getNickname());
        user.setRole(request.getRole() == null ? UserRole.USER : request.getRole());
        user.setEnabled(true);

        // 3) 保存并返回（不要把 passwordHash 返回出去）
        SysUser saved = userRepository.save(user);
        return UserResponse.from(saved);
    }
}
```

自检清单：

- [ ] 密码用了 `passwordEncoder.encode`
- [ ] 存的是 `passwordHash`，不是明文 `password`
- [ ] 重复用户名抛了 `BusinessException`
- [ ] 返回 `UserResponse`，不是 `SysUser`

## 第 4 步：改 `UserController.java`

现在 Controller 直接用了 Repository。按分层习惯，改成调 `UserService`。

### 4.1 注入 Service

把：

```java
private final SysUserRepository userRepository;
```

改成（或同时保留，建议迁移到 Service）：

```java
private final UserService userService;
```

### 4.2 `/me` 可暂时仍用 Repository，或一并迁到 Service

最小改动：`/me` 先不动也可以；先把 create 接上。

更干净做法：`/me` 也改到 `userService.me(loginUser.getId())`。

### 4.3 新增接口

```java
@PostMapping
public ApiResponse<UserResponse> create(@Valid @RequestBody UserCreateRequest request) {
    return ApiResponse.ok(userService.create(request));
}
```

需要的 import：

```java
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
```

注意：当前 `SecurityConfig` 里 `/api/**` 默认要登录，所以这个接口 **必须带 JWT**。这通常符合「后台新增用户」。

## 第 5 步（推荐）：仅管理员可新增

在 `create` 方法上加：

```java
@PreAuthorize("hasRole('ADMIN')")
@PostMapping
public ApiResponse<UserResponse> create(@Valid @RequestBody UserCreateRequest request) {
    return ApiResponse.ok(userService.create(request));
}
```

import：

```java
import org.springframework.security.access.prepost.PreAuthorize;
```

项目里 `SecurityConfig` 已有 `@EnableMethodSecurity`，所以这个注解会生效。

验证点：

- 用 `admin` 登录拿到 token → 能新增
- 若以后有普通用户 token → 应返回 403

```powershell

  -H "Authorization: Bearer 这里换成token" `
```

### 6.4 预期结果

| 场景 | 期望 |
|------|------|
| 参数合法、用户名不存在 | `code=0`，返回新用户（无密码） |
| 未带 token | 401 |
| 非管理员（若加了 PreAuthorize） | 403 |
| 用户名已存在 | 400/业务码，提示已存在 |
| 用户名为空 / 密码太短 | 400，校验信息 |

用新账号再调一次 `/api/auth/login`，应能拿到 token。

## 常见坑

1. **忘了 `@Valid`** → 校验注解不生效  
2. **密码明文入库** → 必须 `passwordEncoder.encode`  
3. **返回了 Entity** → 可能把 `passwordHash` 暴露出去  
4. **角色写成 `"admin"`** → 枚举是 `ADMIN` / `USER`（看 `UserRole`）  
5. **Controller 仍只注入 Repository，却调用了未创建的 Service** → 编译失败  
6. **先写前端再写接口** → 先把 Swagger/curl 测通，再接前端
